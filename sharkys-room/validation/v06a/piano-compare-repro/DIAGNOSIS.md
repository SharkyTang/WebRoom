# Independent normal/debug pixel comparison

**Final resolution:** the runtime now assigns stable name-based `renderOrder` only to registered opaque VIS meshes, keeping original source meshes and transparent materials on their existing ordering. No geometry, source transforms, piano entry or production antialias setting changed. Three new independent cold-loading pairs (`../piano-stable-short-runs.json`) each passed all four comparison phases: 12 whole-canvas comparisons had identical PNG bytes and RGBA with antialias true / samples 4. The final complete 20-cycle regression subsequently passed **10/10 checks**, with 0 changed whole-canvas pixels and no browser errors. Its exact command, times, exit code 0 and code hashes are recorded in `../piano/final-run.json` (2026-09-17T18:03:26.562Z–18:07:17.918Z). The source of nondeterminism was the draw-order dependence of finite-depth contact pixels, amplified by MSAA; fixing stable draw order resolved it without tolerances or disabled antialiasing.

**Later counterexample:** the complete 20-cycle run at 2026-09-17T17:49:54.971Z–17:53:48.498Z passed all eight interaction groups but its AA-disabled control differed at one pixel, canvas (852,401), maximum channel delta 26. Both contexts reported antialias false, samples 0 and depth 24. The complete run, exact comparison arrays and PNGs are preserved in `../piano-controlled-sampling-failure/`. Disabling MSAA alone is therefore not a sufficient deterministic sampling control; the earlier zero-difference pair must not be presented as a stable guarantee. Finite depth precision and material draw order at contact intersections remain relevant with single-sample rendering.

The previous second full-run failure remains unchanged in `../piano-second-pass-failure/`. All reproductions use independent Chrome contexts, 1440×900 viewport, device scale 1 and the same frozen assets. The resulting canvas PNGs are 1080×720. Scene transitions use real canvas mouse clicks, the visible Toggle piano button and Back; diagnostics only read state or hit targets. No selector substitutes for the canvas entry, and no store, camera or asset is mutated.

The failed CLI experiment is retained as a 4× MSAA control and is **not** evidence that disabling AA had no effect. The successful diagnostic override is applied before WebGL context creation in these isolated test pages; it never changes application source or the normal renderer settings.

The first three MSAA pixels are canvas (814,388), (816,388) and (138,415). Actual frozen+production GLB ray casts at nine subpixel positions per pixel map the first two to the pillow/cover contact transition and the third to the rounded door foot/floor transition. `ray-depth-mapping.json` records the ordered intersections. This is not a large coincident front plane, an invisible Piano box becoming visible, PNG metadata, a hover restoration error or a late piano tween: differences already exist before the first click and remain exactly constant within each pair.

The differences vary across fresh page pairs. Their invariance inside each pair, contact-edge location and complete disappearance when actual multisampling is disabled support MSAA depth/coverage ordering as the cause. Asynchronous material/object allocation affecting the opaque renderer's sort order is the likely mechanism; that narrower mechanism has not been independently instrumented.

The actual retracted-entry hit mask contains 5,380 pixel centers in the projected box bounds. It has zero changed pixels in the 10-pixel experiment, but canvas (531,323), which changed in the earlier 2-pixel experiment, is also an actual `PianoRetractedHitArea` hit. Its visible geometry underneath the invisible helper is the desk's rounded left foot/floor contact. Thus an exact mask comparison with MSAA active can also fail from unrelated surfaces behind the invisible target. This is why neither an arbitrary 8-pixel/16-channel cutoff nor choosing a successful pair establishes reliable exact entry-region equivalence.

All exact pixel arrays and parameter/state snapshots are retained in the corresponding `result.json`, with normal/debug/difference PNGs for every phase. The AA-disabled pair provides a strict whole-canvas control; it must be described as a controlled diagnostic comparison, not proof that the normal AA-enabled frames are byte-identical across cold page loads.
